## Authority and lifecycle

Existing `/admin?section=Sessions` retains single-session creation and status actions. Operational discovery returns at most 50 rows plus `hasMore`, ordered by start/id, filtered by cohort/state/start-window. Dates are inclusive-from/exclusive-until. Original/replacement links can inspect one exact canonical record. Legacy pickers are bounded to 200 cohorts/500 lessons; batch activation discovery is navigable in pages of 200 records, and activation lessons in pages of 250. Both lists expose Previous/Next navigation and truthful page-specific hasMore. These are page sizes, never product/domain limits.

Academic Admin and Platform Admin are independently required at the server and database. Registrar, Instructor, Counsellor and learner roles cannot mutate schedules. Identity and role checks use the existing authenticated authority root. Deactivated actors have no authority.

OPEN and CLOSED permit delivery. COMPLETED refuses new single sessions, replacements and batches. Cohort `starts_on`/`ends_on` remain metadata and are not new teaching constraints. No package scheduling defaults, DELIVERY_V1 preferences, recurrence, timezone recurrence or inferred durations are applied. Existing creation still permits explicit historical intervals; rescheduling alone is future-only.

## Contracts

`reschedule_class_session(p_session_id uuid, p_scheduled_start timestamptz, p_request_id uuid, p_reason text)` derives cohort/version/lesson/instructor and exact elapsed duration from the original. Only an unstarted SCHEDULED original and future replacement are permitted. It cancels the immutable original and inserts its replacement atomically. Attendance, evidence, progress and classroom history are never moved. Existing history also refuses replacement. Unique receipt predecessor and unique item session enforce one successor. Failed replacement rolls back cancellation.

`generate_class_session_batch(p_request_id uuid, p_activation_id uuid, p_instructor_id uuid, p_items jsonb, p_reason text)` accepts 1-100 strict `{lessonId, scheduledStart, scheduledEnd}` items with explicit offset-bearing instants. 100 is a per-request operational bound, not a global schedule cap: additional independent batches remain possible. The activation determines cohort/version/import. Its instructor is the UI default but any ACTIVE qualified instructor may be confirmed. Lessons must have exact activation provenance. Internal overlaps/duplicates, existing cohort/instructor overlaps and exact cancelled-history matches refuse the whole batch. No silent skipping or activation rerun occurs.

Receipt fingerprints normalize instants to UTC and sort batch rows deterministically. Reason is bounded to 5-300 characters and belongs to the first successful audit receipt, not the replay fingerprint. Request UUID is shared across both operation kinds. Identical request/fingerprint returns the original result without inserting or auditing again; differing payload refuses. Replay returns historical session IDs even if subsequently cancelled, without regeneration.

## Navigable activation and lesson discovery

`admin_class_session_batch_options(p_activation_id uuid default null, p_activation_offset integer default 0, p_lesson_offset integer default 0)` independently pages activations ordered by `created_at,id` and selected-activation lessons ordered by `module.position,lesson.position,lesson.id`. Each reads only one extra row beyond its 200/250 page to determine current-page `hasMore`/`lessonsHasMore`. The response echoes `activationOffset`/`lessonOffset`, includes the bounded page arrays, and returns a separate nullable `selectedActivation` record. Direct selection stays usable even if that activation is not on the current activation page.

Server/domain input validates decimal offsets in 0-2,147,483,647 (the PostgreSQL integer transport range); negative, fractional, malformed and overflowing offsets refuse. URL fields are `activationId`, `activationOffset` and `lessonOffset`. Previous/Next links retain selected activation and independent page state. Selecting another activation resets the lesson offset. Paging starts a new batch preview; submit the current preview before navigating. A batch need not span lesson pages: any reachable mapped lesson can be scheduled in an additional independent batch. Default offsets zero preserve first-page behaviour.

## Locks, ACL and audit

Lock order is request advisory lock, cohort, target instructor `app_users` FOR UPDATE, staff profile, original session when applicable. Legacy creation uses the same cohort/app-user/staff order. Instructor account, staff profile and INSTRUCTOR grant are checked under the target app-user lock. Migration 044 People mutations lock that same target before deactivation/revocation/live-teaching decisions. No People authority or guard is rewritten. Cohort locks serialize completion and cohort conflicts; instructor locks serialize cross-cohort scheduling conflicts. Existing immutable-history triggers remain intact. A private BEFORE INSERT guard on `professor_classroom_sessions` takes FOR SHARE on the referenced `class_sessions` row, then rejects a missing or CANCELLED parent. FOR SHARE conflicts with reschedule FOR UPDATE and remains held through the classroom transaction. A stale opener waiting behind reschedule must re-read the committed cancellation and refuse; existing classroom rows are never moved or rewritten. Migration 026's opening RPC remains unchanged.

Focused tests inspect effective ACLs through migration 048 under broad Supabase-like defaults and observe service-role INSERT. Migration 049 revokes application table INSERT/UPDATE/DELETE/TRUNCATE/TRIGGER and column INSERT/UPDATE while preserving reads and owner setup. New receipt/item tables are RLS-enabled, application RPC-only and append-only; private helpers and inherited function grants are revoked. A closing effective-ACL assertion fails deployment if anon/authenticated/service_role retain any class-session table writes or column INSERT/UPDATE, any receipt/item table or column access (including MAINTAIN where supported), private schema USAGE/CREATE or private helper EXECUTE. It also requires authenticated class-session SELECT and compares EXECUTE against the exact five reviewed public RPC signatures; unexpected overloads or inherited grants fail closed. Tests deliberately grant privileges through inherited roles and execute the actual deployment assertion to prove refusal. Public RPCs are authenticated and independently authorize each call, including replay. Expected errors map to allowlisted institutional messages; unexpected SQL text is never rendered.

Individual class-session audit triggers remain. Named reschedule audit includes actor, original/replacement, old/new times and bounded reason. Batch audit contains actor, activation/cohort/instructor, request and count; durable item mapping contains session IDs. No unrelated learner prose, credential or payment payload is stored.
