## Phase 3 checkpoint 1D-B1 — provider-neutral trusted execution governance

The interrupted B1 working tree was resumed in place at `902e915`, preserving the prior implementation. Migration `202609100022_phase3_trusted_execution_governance.sql` adds `academic_execution_private.controller_keys`, `academic_executions`, constrained `govern_professor_execution` commands and dedicated metadata-only audit/immutability triggers. It uses Node and pgcrypto HMAC-SHA256 instead of introducing a service-role credential or a new application SQL connection. No dependency or provider was added.

The authenticated human STUDENT session and an independently verified controller attestation are both required. The database derives learner identity, fixes PROFESSOR/policy, verifies the owned ACTIVE academic release and its immutable invocation, and independently enforces state, budget and admission rules. The canonical protocol binds key/learner/execution/release, operation, outcome/reason, budget and issuance/expiry. Attestations expire after ten seconds with at most five seconds of tolerated forward server-clock skew; DB time is authoritative and verification repeats after the shared learner lock. Captured AUTHORIZE/START/terminal commands cannot create a second transition. Migration 021's 30-second release and all nine V2 capability contracts remain unchanged.

Execution states distinguish AUTHORIZED, RUNNING, SUCCEEDED, FAILED, ABSTAINED, ESCALATED and admission BLOCKED. The B1 runtime deliberately records ABSTAINED/POLICY_BLOCKED and returns metadata only; SUCCEEDED is exercised solely by explicit control-plane lifecycle fixtures. Security ceilings are one concurrent execution, five admissions per 60 seconds and 30 per hour, with a maximum 20-second execution capped by the bound release expiry. B1 budgets are zero provider calls, zero input/output tokens and zero estimated micro-USD; no actual usage/cost is recorded. These are pre-production abuse ceilings, not subscription quotas.

The existing gateway admits controller composition only for the seven validated content reads inside their release. It preserves exact self/enrolment/version checks, fresh principal validation and EXPLAIN enforcement. Invalid/malformed/audit-failed transitions and release-close failures discard the result. Terminal execution history and identity are immutable, deletion is forbidden, and authenticated users cannot directly read/mutate execution/key tables or forge institutional audit writes.

The trust claim is narrow: a valid MAC proves that a holder of the Ducelio controller secret authorized the exact command; DB audit records the permitted resulting control-plane lifecycle. It does not prove provider execution, model correctness or content delivery. RPCs remain directly authenticated-callable but additionally require the MAC; they are never described as gateway-only. No standalone generic verifier, signing oracle or arbitrary payload writer is exposed. The govern_professor_execution RPC necessarily validates a MAC only for its fixed, typed execution-governance protocol. Prompts, outputs, academic/support/assessment prose, evidence references, learner responses, credentials, MACs and sensitive-content hashes do not enter execution/audit rows. Exact metadata-retention duration remains a production governance decision.

No production secret was provisioned. The private DB key store starts empty; the server requires matching server-only secret-manager environment values. Operator provisioning, rotation, backup/log protection and hosted pgcrypto/RPC grants must be accepted separately. The full design, canonical format, alternatives, failure policy and B2 prerequisites are in `15-academic-execution-governance.md`.

A stored configuration only ever narrows what may be requested — the server independently re-checks, at execution time, both that a capability is in the code-owned catalogue **and** that the stored configuration actually requested it.

The B2 runtime (`src/domain/academic-runtime.ts`, `src/domain/academic-runtime-profile.ts`, `src/server/academic-runtime/*`) is a complete, standalone, fully tested provider-neutral harness: a `ProviderAdapter` port with no vendor SDK; a fail-closed, HTTPS-only, userinfo-rejecting, non-redirecting `resolveConfiguredProvider()`; a **code-only runtime/model-profile registry** (ships empty — no provider choice has been made — so a stored `modelProfileRef` is only ever a lookup key that fails closed before any provider call, including a URL- or credential-shaped value); and `runGovernedProviderExecution`, which is explicit about pre-call **hard** ceilings (admission, a byte-length context-size ceiling, and one `totalDeadlineMs` shared across every retry attempt so attempts can never multiply a nominal execution window) versus post-call usage **reconciliation** (output-token and monetary-cost overage, which a call may still incur even though its response is discarded — a `BUDGET_BLOCKED` result's `stage` field distinguishes the two). `executeRoleCapability(request)` — the **production entrypoint, with no override parameter at all** — composes authenticated-STUDENT identity, the existing 2A institutional delivery-agent-access lifecycle (`getDeliveryAgentAccess`, not a parallel activity check), stored agent configuration, code-owned capability authorization and profile resolution, then — for PROFESSOR only — calls the existing `PROFESSOR_READ_V2` gateway's release-aware `withValidatedProfessorContent` and runs the provider call **inside that gateway's own consumer callback, while its content-release lease is still open**. **The problem closed:** migration 031's `commercial_v1_examiner_executions` admits exactly one claim per target, by design. A terminal `FAILED`/`TIMEOUT`/`BUDGET_BLOCKED`/`CANCELLED` initial execution therefore permanently strands its target with no result revision, and migration 032's regrade cannot recover it — regrade's source resolver requires an _existing_ result to supersede, and there is none.

**Design:** a separate, dedicated authority (`commercial_v1_examiner_recovery_executions`, `govern_commercial_v1_examiner_recovery`, policy `COMMERCIAL_V1_EXAMINER_INITIAL_RECOVERY_V1`), not an extension of regrade — reusing the shared reviewed primitives (the controller-key HMAC trust root, migration 030's atomic-finalizer/result-integrity helpers) while keeping identity, protocol tag and unique-claim semantics fully separate from both initial grading and regrade. Eligibility is explicit, not inferred: `FAILED`/`TIMEOUT`/`BUDGET_BLOCKED`/`CANCELLED` originals with no existing result are RECOVERABLE; `ESCALATED` (an explicit human-review determination), `AUTHORIZED`/`RUNNING` (still active) and `SUCCEEDED` (already has a result — regrade's job) are NOT RECOVERABLE. Exactly one recovery claim is ever admitted per original execution (`examiner_recovery_one_per_source`, a single-column unique index) — if that one attempt also terminates without a result, the target is a durably auditable known-stranded state requiring a future, separately reviewed mechanism, never a second automatic recovery. Recovery reuses the _same_ programme-version `academic_agent_configs` EXAMINER config gate migration 036 added to initial grading (deliberately not regrade's unconditional admin-override model): a disabled/unconfigured capability correctly blocks both initial grading and its recovery through the one toggle an admin controls, and a direct `ESCALATED` claim is created when `escalationPolicy=ACADEMIC_REVIEW`, zero provider calls. Authority is `ACADEMIC_ADMIN`/`PLATFORM_ADMIN` only, re-verified server-side before and after the enrolment lock; recovery accepts only `{sourceExecutionId, reason}` — no marks, score, weight, provider/model choice or learner-identity override exists on the input schema. The original failed execution is never mutated; the recovery reason is stored on the protected execution row only, never in generic audit JSON, never in provider context.

`src/server/commercial-v1-examiner-recovery/{authority,context,index}.ts` mirror regrade's module shape for HMAC/table plumbing but `index.ts`'s AUTHORIZE/profile-resolution ordering mirrors initial grading's config-aware `gradeExaminerTarget`: a pre-AUTHORIZE budget proposal never widens what the DB actually admits, and the runtime profile actually executed is re-resolved strictly from the DB-admitted snapshot's own immutable `runtimeProfileRef`.
