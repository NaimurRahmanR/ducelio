The authenticated human STUDENT session and an independently verified controller attestation are both required. The canonical protocol binds key/learner/execution/release, operation, outcome/reason, budget and issuance/expiry. Attestations expire after ten seconds with at most five seconds of tolerated forward server-clock skew; DB time is authoritative and verification repeats after the shared learner lock. Captured AUTHORIZE/START/terminal commands cannot create a second transition. Migration 021's 30-second release and all nine V2 capability contracts remain unchanged.

Execution states distinguish AUTHORIZED, RUNNING, SUCCEEDED, FAILED, ABSTAINED, ESCALATED and admission BLOCKED. The B1 runtime deliberately records ABSTAINED/POLICY_BLOCKED and returns metadata only; SUCCEEDED is exercised solely by explicit control-plane lifecycle fixtures. Security ceilings are one concurrent execution, five admissions per 60 seconds and 30 per hour, with a maximum 20-second execution capped by the bound release expiry. B1 budgets are zero provider calls, zero input/output tokens and zero estimated micro-USD; no actual usage/cost is recorded. These are pre-production abuse ceilings, not subscription quotas.

The existing gateway admits controller composition only for the seven validated content reads inside their release. Terminal execution history and identity are immutable, deletion is forbidden, and authenticated users cannot directly read/mutate execution/key tables or forge institutional audit writes.

The trust claim is narrow: a valid MAC proves that a holder of the Ducelio controller secret authorized the exact command; DB audit records the permitted resulting control-plane lifecycle. It does not prove provider execution, model correctness or content delivery. RPCs remain directly authenticated-callable but additionally require the MAC; they are never described as gateway-only. No standalone generic verifier, signing oracle or arbitrary payload writer is exposed. The govern_professor_execution RPC necessarily validates a MAC only for its fixed, typed execution-governance protocol. A stored configuration only ever narrows what may be requested — the server independently re-checks, at execution time, both that a capability is in the code-owned catalogue **and** that the stored configuration actually requested it.

The B2 runtime (`src/domain/academic-runtime.ts`, `src/domain/academic-runtime-profile.ts`, `src/server/academic-runtime/*`) is a complete, standalone, fully tested provider-neutral harness: a `ProviderAdapter` port with no vendor SDK; a fail-closed, HTTPS-only, userinfo-rejecting, non-redirecting `resolveConfiguredProvider()`; a **code-only runtime/model-profile registry** (ships empty — no provider choice has been made — so a stored `modelProfileRef` is only ever a lookup key that fails closed before any provider call, including a URL- or credential-shaped value); and `runGovernedProviderExecution`, which is explicit about pre-call **hard** ceilings (admission, a byte-length context-size ceiling, and one `totalDeadlineMs` shared across every retry attempt so attempts can never multiply a nominal execution window) versus post-call usage **reconciliation** (output-token and monetary-cost overage, which a call may still incur even though its response is discarded — a `BUDGET_BLOCKED` result's `stage` field distinguishes the two). `executeRoleCapability(request)` — the **production entrypoint, with no override parameter at all** — composes authenticated-STUDENT identity, the existing 2A institutional delivery-agent-access lifecycle (`getDeliveryAgentAccess`, not a parallel activity check), stored agent configuration, code-owned capability authorization and profile resolution, then — for PROFESSOR only — calls the existing `PROFESSOR_READ_V2` gateway's release-aware `withValidatedProfessorContent` and runs the provider call **inside that gateway's own consumer callback, while its content-release lease is still open**. Any already-captured provider output is discarded if the gateway's own final principal/activity recheck fails or its release finalization fails afterward, and zero provider calls occur if the gateway denies the capability/release before the callback ever runs. Every role other than PROFESSOR fails closed with `NO_EXECUTION_PATH`: no bounded, correctly-provenanced context builder exists for TUTOR/LAB_INSTRUCTOR/EXAMINER/COUNSELLOR yet, so a placeholder catalogue entry is never treated as a live execution path. Dependency injection for tests is isolated in a separate `executeRoleCapabilityWithTestOverrides` entrypoint, which itself refuses to run under `NODE_ENV=production` before touching any injected adapter/profile resolver — so an injected dependency is structurally unreachable in production, not merely discouraged by convention. A `DeterministicFakeProviderAdapter` exists **only** for tests, likewise refuses to construct under `NODE_ENV=production`, and is never returned by the production resolver or registry.

This runtime is deliberately **not** spliced into `executeProfessorRead`/`govern_professor_execution` (migration 022) in this checkpoint: that RPC's admitted envelope is zero provider calls by explicit, previously reviewed design (`15-academic-execution-governance.md`), and raising it is its own separately reviewed migration, not a side effect of adding an adapter interface. ## Commercial V1 — Live Professor Provider-Backed Execution

Starting branch `commercial-v1-live-professor-execution` was clean at the verified, merged `2a3cb013b5a79a4e2b814c15398b62ddb182a698` (PR #5). Full design, ordering guarantees and the critical-success-rule proof are in `19-live-professor-execution.md`; this entry summarises it.

The composition order inside `executeRoleCapability` is: authenticate → 2A delivery access → agent configuration/capability authorization → runtime/model profile resolution → the existing `withValidatedProfessorContent` gateway begins its own academic-content release → **inside that release's still-open callback**, AUTHORIZE then START the V2 execution, then run the provider (`runGovernedProviderExecution`) with an effective runtime policy built from the profile but with `maxProviderCalls`/`maxOutputTokens`/`maxEstimatedCostMicrousd` replaced by the exact capped/admitted proposal, capturing its `RuntimeResult` → return from the callback (no FINALIZE yet, the execution is left `RUNNING`) → only once the gateway itself has performed its final principal/activity recheck and closed the release successfully is FINALIZE called, durably reconciling the actual usage and terminalizing the V2 execution in one trusted transaction. A `SUCCEEDED` response escapes to the caller only once that FINALIZE call is itself confirmed by the database with a terminal state matching exactly what was requested; any release/gateway/FINALIZE failure discards the response (returns `ABSTAINED`), and the returned `RuntimeResult` still carries the real usage a provider call actually consumed rather than a zero placeholder — though that usage is durably persisted only when the FINALIZE call itself is confirmed; if FINALIZE cannot be confirmed, the row instead resolves later under the DB's own timeout/reconciliation handling. `mapRuntimeResultToFinalizeCommand` (`src/domain/academic-provider-execution.ts`) is a pure function honestly mapping every `RuntimeResult` outcome (`SUCCEEDED`/`FAILED`/`ABSTAINED`/`ESCALATED`/`BUDGET_BLOCKED` with `PRE_CALL`/`POST_CALL` stage/`TIMEOUT`/`CANCELLED`) onto this bounded vocabulary, strictly validating the real usage against the durable ledger's own bounded schema rather than silently clamping it.

`public.academic_provider_execution_usage` closes the previously-documented durable-usage-ledger gap: exactly one immutable row per execution (provider calls, attempts, input/output tokens, estimated cost, elapsed time only — no prompt, response or any other content field exists anywhere in the schema), written once by FINALIZE and permanently guarded against update/delete. Only the reviewed `govern_professor_provider_execution` RPC (SECURITY DEFINER, MAC-verified, authenticated-learner-scoped) can ever write either table; both are revoked from `public`/`anon`/`authenticated`/`service_role` directly, closed by the same effective-ACL assertion pattern as migrations 022/024.
