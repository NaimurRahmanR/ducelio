# Commercial V1 — Examiner Initial-Grade Failure Recovery

## Scope

Starting branch `commercial-v1-grading-completion`, clean at exact `origin/main` `6b47aa366b77f3aac8166576363fa7edec80dbb7` (PR #25, the closed-green backend-integrity correction: PR-head CI `35676062246` and post-main CI `35677545793` both SUCCESS, independently verified via `gh pr checks 25` / `gh run list --branch main`). Migrations 001–039 are byte-for-byte unchanged; the only migration this checkpoint adds is `202609240040_commercial_v1_examiner_initial_grade_recovery.sql`.

## The problem this closes

Migration 031's `commercial_v1_examiner_executions` has a partial unique index on `attempt_id` and on `submission_id`: exactly one admitted claim is ever created per target, by design (docs/25's "initial grade only" guarantee). This means a terminal, unsuccessful initial execution — `FAILED`, `TIMEOUT`, `BUDGET_BLOCKED` or `CANCELLED` — permanently occupies its target while producing **no result revision**. Migration 032's regrade authority cannot recover it: `commercial_v1_regrade_private.source` resolves its source strictly from an **existing** result revision, and there is none. Without this checkpoint, such a target is permanently stranded — not gradeable, not regradeable, no institutional path to a result.

## Design choice: a separate authority (Option B), not an extended regrade (Option A)

Option A (extending regrade to accept a no-result source) was rejected after reading regrade's actual implementation: its source resolver, its `NOT_CURRENT_RESULT`/`CURRENT_RESULT_INVALID` checks and its `revision_number = src.revision_number + 1` insert all assume an **existing** result to supersede. Overloading that single code path to sometimes mean "no result exists yet" would blur two structurally different authorities — superseding a judged grade versus giving a never-graded target its legitimate first attempt — for no line-count benefit: a new claim table, a new HMAC protocol tag and new AUTHORIZE eligibility logic are required either way.

Instead, `commercial_v1_examiner_recovery_executions` is a **separate, dedicated** claim table and governed RPC (`govern_commercial_v1_examiner_recovery`), policy `COMMERCIAL_V1_EXAMINER_INITIAL_RECOVERY_V1`, execution kind `PROVIDER_BACKED_RECOVERY_V1`, protocol tag `DUCELIO_COMMERCIAL_V1_EXAMINER_RECOVERY_HMAC_SHA256_V1`. It reuses the shared reviewed primitives that are semantically identical across initial grading, regrade and recovery — the `academic_execution_private.controller_keys` HMAC trust root, migration 030's atomic-finalizer/result-integrity helpers, the grade-digest/mark-validation shape — while keeping each surface's own identity, protocol tag and unique-claim semantics fully separate. A regrade attestation can never authorize a recovery transition, and vice versa, without a second key.

## Eligibility policy — explicit, not inferred

Every original terminal state is classified, on the actual current migration-031 lifecycle, not guessed:

| Original state                                            | Recovery eligibility | Why                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FAILED` (any reason, including `NO_PROVIDER_CONFIGURED`) | **RECOVERABLE**      | An infra/config/provider condition, not a determination about the learner's work. `NO_PROVIDER_CONFIGURED` is in the same bucket as `PROVIDER_UNAVAILABLE`/`PROVIDER_TIMEOUT`/etc. — the grading attempt itself broke, nothing was decided.                                                                                                       |
| `TIMEOUT` (reason `EXECUTION_TIMEOUT`)                    | **RECOVERABLE**      | Same bucket: the attempt never completed.                                                                                                                                                                                                                                                                                                         |
| `BUDGET_BLOCKED`                                          | **RECOVERABLE**      | A budget-envelope condition, not a content determination.                                                                                                                                                                                                                                                                                         |
| `CANCELLED`                                               | **RECOVERABLE**      | Never reached a determination.                                                                                                                                                                                                                                                                                                                    |
| `ESCALATED` (`HUMAN_REVIEW_REQUIRED`)                     | **NOT RECOVERABLE**  | An explicit institutional "this needs human academic review" determination — either config-driven at AUTHORIZE (migration 036's `escalationPolicy=ACADEMIC_REVIEW`) or provider-driven via a genuine `{"outcome":"ESCALATE"}` response. Re-running the same automated Examiner path would not resolve that determination and would circumvent it. |
| `AUTHORIZED` / `RUNNING`                                  | **NOT RECOVERABLE**  | Still active, not terminal.                                                                                                                                                                                                                                                                                                                       |
| `SUCCEEDED`                                               | **NOT RECOVERABLE**  | Already has a result; migration 032's regrade is the correct authority for a dispute over an existing grade, never this one.                                                                                                                                                                                                                      |

`commercial_v1_recovery_private.original(source_execution_id, target_kind)` resolves the original row and computes `is_eligible` (`state in ('FAILED','TIMEOUT','BUDGET_BLOCKED','CANCELLED')`) and `is_result_free` (independently re-confirms no result revision exists for the same enrolment/component or enrolment/practical, defense-in-depth on top of the one-slot-per-target guarantee) in one query. `p_target_kind` is part of the resolver's `WHERE` filter, not a post-hoc comparison, so a capability/target-kind mismatch is indistinguishable from a nonexistent `source_execution_id` — the same bounded-denial convention every other cross-target lookup in this codebase uses.

## Recovery ceiling — exactly one claim, ever

`examiner_recovery_one_per_source` is a single-column unique index on `source_execution_id` (not a compound `(target_kind, source_execution_id)` like regrade's, since migration 031's own per-target uniqueness already makes `source_execution_id` alone unambiguous). This mirrors the "one claim per target, ever" philosophy migration 031 established for the _original_ claim, extended one level: if the one admitted recovery attempt **also** terminates without a result, the target becomes a durably auditable, known stranded state (two terminal claims, still zero results) — never a second automatic recovery. A future, separately reviewed institutional mechanism (manual grade entry, or a deliberately new "recovery of a recovery" authority) is required to go further; this checkpoint does not invent one, matching PR11B1's own "no automatic retry after terminal" precedent.

AUTHORIZE resolves an existing recovery claim for the exact `source_execution_id` **first** — before eligibility, rate limits or config governance — mirroring migration 031's own Blocker-2 fix: a prior claim, terminal or active, must always be observed on its own terms (preserving a `SUCCEEDED` recovery's own `resultRevisionId`) rather than being discarded by an unrelated denial.

## Configuration governance — the same gate as initial grading, not regrade's override model

Recovery reuses the **exact same** capability vocabulary as initial grading (`grade_controlled_assessment`/`grade_practical_lab`, never a separate `regrade_*` pair) and the **exact same** programme-version `academic_agent_configs` EXAMINER row/lock migration 036 added to initial grading's own AUTHORIZE: `enabled`, the invoked capability present in `capabilities`, `resolve_role_profile_ref('EXAMINER', model_profile_ref)`, and a direct durable `ESCALATED` claim (zero provider calls) when `escalation_policy='ACADEMIC_REVIEW'`. This is a deliberate choice against regrade's unconditional admin-override model: recovery is "let the governed automated Examiner pipeline have its one legitimate first attempt", not "an admin manually overrides an existing judged grade". An institution that has disabled AI-assisted grading for a course, or not enabled the grading capability, correctly blocks both initial grading and its recovery through the one toggle an admin actually controls.

## Authority — ACADEMIC_ADMIN / PLATFORM_ADMIN only

`requireRecoveryActor()` (TypeScript) and the database's own role check (re-verified before and after the enrolment/student locks, exactly like migrations 031/032) both require a fresh authenticated `ACADEMIC_ADMIN` or `PLATFORM_ADMIN`. A learner cannot trigger recovery merely by refreshing or resubmitting — `recoverControlledAssessmentGrade`/`recoverPracticalLabGrade` accept only `{sourceExecutionId, reason}`; there is no field through which a caller could supply marks, score, weight, a previous proposed grade, provider/model choice or a learner-identity override.

## Protected context — the same immutable original work, never the recovery reason

CONTEXT_READ is implemented inline inside `govern_commercial_v1_examiner_recovery` (mirroring regrade's own inline pattern, not migration 031's separate context RPCs — those are bound to the _original_ execution's id, which can never be `RUNNING` again once terminal). It returns the exact same authoritative shape as initial grading/regrade: answered questions with expected answer/marking guidance/the learner's own latest response (assessment), or the practical/policy/submission/objectives (lab). It never includes the recovery reason, the original failure reason, a previous grade, or any audit metadata — `getRecoveryContext` (`src/server/commercial-v1-examiner-recovery/context.ts`) strictly re-validates the returned shape and re-checks target identity before forwarding only the bounded context object to the provider request.

## Atomic finalizer — the critical success rule, reused

FINALIZE's `SUCCEEDED` branch is byte-for-byte the same critical-success-rule shape as migrations 031/032: the enrolment row lock is acquired before the transaction's first authoritative observation (not re-acquired at FINALIZE), grade digest is independently recomputed and checked, marks are re-validated against the real authoritative question/practical set, `commercial_v1_private.derive_and_insert_objective_outcomes`/`assessment_result_is_valid` (migration 030, unmodified) are reused directly, and `revision_number` is hard-coded to `1` — never `src.revision_number + 1` like regrade — because by construction (the `is_result_free` re-check plus `guard_assessment_result_insert`'s own revision-1-uniqueness `CHECK`, both independently proving the same invariant) no revision can already exist. Any exception inside the nested `begin...exception` block rolls back every result-side write and records `FAILED`/`RESULT_INTEGRITY_FAILED` instead — a result can never exist while its recovery execution remains non-successful, and the execution can never be `SUCCEEDED` while its result is missing or invalid.

## TypeScript orchestration

`src/server/commercial-v1-examiner-recovery/{authority,context,index}.ts` mirror regrade's own module shape (a dedicated table, its own HMAC transport, actor-scoped continuation) for the plumbing, but `index.ts`'s AUTHORIZE/profile-resolution ordering mirrors initial grading's config-aware `gradeExaminerTarget` instead: a pre-AUTHORIZE profile proposal (via `resolveRoleBoundRuntimeProfile("EXAMINER", null)`) only ever bounds the _proposed_ budget envelope; the profile actually used to execute is re-resolved strictly from the DB-admitted snapshot's own immutable `runtimeProfileRef` after AUTHORIZE returns, never re-defaulted from `null`. A direct config-governed `ESCALATED` claim short-circuits before any profile re-resolution, START or provider call.

`providerEntered` (distinct from `started`) tracks whether `runGovernedProviderExecution` was actually invoked, separately from whether a result was captured: `lastKnownUsage()` returns the real captured usage when available, `zeroUsage()` only when the provider was never entered, and `null` (skipping any cleanup FINALIZE, leaving the execution to the DB's own 20-second expiry) when the provider was entered but its outcome is genuinely unknown — never a synthetic zero usage record for an uncertain provider call. This was found and fixed during this checkpoint's own runtime tests (a raw provider-transport throw, distinct from a `RecoveryDenied`/`ExaminerExecutionDenied`, is caught here — unlike initial grading's `gradeExaminerTarget`, which only catches `ExaminerExecutionDenied` and rethrows anything else; recovery's broader catch matches regrade's more defensive pattern instead).

## Security

Cross-student/foreign-target access is bounded and non-leaking: a nonexistent `source_execution_id` and a capability/target-kind mismatch against a real one both return the identical `NOT_FOUND_OR_FORBIDDEN`. `anon`/`service_role` cannot invoke the governed RPC or read either new table directly — proven by a dedicated ACL test and closed by the same deployment-time effective-privilege assertion pattern as migration 031 (stronger than migration 032's revoke-only pattern; the more rigorous of the two established patterns was chosen deliberately). The controller-key HMAC trust root, strict provider JSON parsing, grade-digest recomputation and content-minimised audit (`recovery_reason` lives only on the protected execution row, never in the generic `audit_events.after_state` JSON) are all reused unmodified from the existing reviewed infrastructure.

## Known limitations

- **PGlite cannot prove true multi-connection PostgreSQL concurrency.** The one-claim-per-source guarantee rests on a real unique-index constraint and an `insert ... on conflict do nothing` race-safe by Postgres's own construction; this checkpoint proves the constraint directly (a second raw insert for the same `source_execution_id` is rejected) and the AUTHORIZE replay-first ordering sequentially, not via two genuinely concurrent connections. Hosted true-concurrency acceptance remains a Checkpoint D requirement, unchanged from every prior Examiner checkpoint's own documented limitation.
- **A terminal recovery outcome permanently occupies its one claim.** If the single admitted recovery attempt also fails, times out, is budget-blocked or is cancelled, the target remains stranded with no further automatic path — by design (see "Recovery ceiling" above). A future, separately reviewed authority is required for that residual case.
- No admin discovery/listing surface exists yet for finding eligible stranded targets — this checkpoint is the governed write authority only; a bounded `list_*` read is left to a later checkpoint composing the full grading/results chain.
- No hosted provider call was made or attempted in this session.
